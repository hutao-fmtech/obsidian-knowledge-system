# 10-卡片盒 - Zettelkasten 永久笔记

本目录是知识库的核心——个人用自己的话提炼的永久笔记，与 `04-资源/` 的外部参考相对。

## 四种卡片类型与归属

| 子目录 | 用途 | 判断标准 |
|--------|------|---------|
| `概念卡片/` | 定义和解释核心概念 | "X 是什么？" |
| `方法卡片/` | 可复用的方法论/流程 | "如何做 X？" |
| `观点卡片/` | 个人洞察和思考 | "我认为 X…" |
| `索引卡片/` | MOC 知识地图，导航入口 | 汇聚多张相关卡片 |

## 创建卡片的约束

- **原子化**：一张卡片只讨论一个概念，不超过 800 字
- **用自己的话**：不直接摘抄，重新理解后表达
- **至少 2 个双向链接**：`[[相关笔记]]`，不允许孤岛
- 卡片来源通常是 `04-资源/` 的阅读/调研内容提炼而来

## 卡片提取工作流

**从参考资料到卡片的步骤**：
1. **标记关键段落**：在 `04-资源/` 文件中高亮核心观点
2. **提炼核心概念**：问"这段话的本质是什么？"
3. **用自己的话改写**：闭上文档，凭记忆写出理解
4. **添加个人思考**：这与我已知的 X 概念有何关联？
5. **建立链接**：至少链接 2 个相关卡片，形成知识网络

**示例**（好的卡片）：
```markdown
# Agent 消息传递机制

在多 Agent 系统中，消息传递采用异步队列模型。
每个 Agent 维护独立的收件箱，通过 SendMessage 工具
发送消息时不阻塞发送方，接收方在下一轮次处理。

这类似于 Actor 模型，避免了同步调用的死锁问题。

相关：[[Actor 并发模型]] [[事件驱动架构]]
```

**反例**（坏的卡片 - 直接摘抄）：
```markdown
# Agent Teams 功能

根据官方文档，Agent Teams 支持以下功能：
1. 创建团队
2. 分配任务
3. 发送消息
...（大段复制粘贴）
```

## Frontmatter

`type` 按子目录 README 的 `slot.accepts` 选（Concept Card / Method Card / Opinion Card / MOC），完整字段见 `00-系统/Frontmatter 规范.md`。

## 索引卡片（MOC）命名规范

- 文件名格式：`MOC-主题名称.md`
- 需包含 10+ 个链接到相关卡片
- 作为主题的导航入口，不写原创内容

## 与其他目录的关系

- **来源**：从 `04-资源/` 中的外部资料提炼
- **产出**：为 `30-输出/` 的创作提供素材
- **区别于 `04-资源/`**：那里是原始参考资料（阅读笔记/AI整理资料等），这里是经过消化的个人理解
